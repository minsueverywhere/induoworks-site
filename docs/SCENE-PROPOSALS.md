# 씬 내부 편집·Discord 참여자 작성본

2026-10-17 사용자가 Discord 로그인·서버 권한 구현 보류를 해제했다. 마을 외관은 호스트가 관리하고, 승인된 Discord 계정은 자기 업체의 작품과 집 내부만 편집한다. **사이트 코드·콘텐츠·D1·Discord 설정은 운영 반영 완료**이며 실제 계정의 로그인·작품 입력/저장/새 탭 복원·실내 층/음악 배치·변경 요청·호스트 목록/반려를 확인했다. 변경안 파일의 실제 다운로드·로컬 가져오기·미리보기·변경 버리기도 확인했다. 요구사항과 실제 진행 상태는 [이슈 #2](https://github.com/minsueverywhere/induoworks-site/issues/2), 호스트 로컬 도구는 [CONTENT.md](CONTENT.md)를 따른다.

## 현재 구현 계약

- 공개 홈의 ‘내 작업실’을 누를 때 참여자 UI/CSS를 동적으로 읽는다. 평소에는 로그인·편집 코드나 음원을 초기 로딩하지 않는다.
- Discord `identify` authorization code flow, 브라우저에 묶인 10분·일회성 state, 서버에서 토큰 교환과 사용자 조회, 7일 세션을 사용한다. Discord 토큰은 저장하지 않는다. 세션 원문은 Secure·HttpOnly·SameSite=Lax·__Host 쿠키, 해시는 D1에 둔다.
- `studio_members`의 Discord ID → 업체 ID를 매 요청에 확인한다. 공개 JSON에는 계정 ID·권한·작성본·요청을 넣지 않는다. 별도 `studio_hosts`에 등록한 계정만 전체 요청을 검토한다. 호스트 ID도 공개 설정이나 Git에 두지 않는다.
- 참여자는 자기 업체만 소속된 Work·이미지·음악 데이터와 `workers[].room` 사본을 수정한다. 공유 제작 작품과 다른 업체 데이터, 집 외부 위치, 마을 지형·공지, 권한 연결을 변경할 수 없다. 내 집 선택·씬 편집·실행 취소·작성본 저장·변경 요청을 제공한다.
- **새 파일 업로드는 호스트가 등록**한다. 참여자는 이미 승인된 파일을 선택하거나 Work에 `externalUrl`을 등록한다. 새 업로드 파일 경로는 서버에서 거부하며, 외부 링크는 아래 지원 출처만 허용한다. R2·참여자 직접 파일 업로드는 도입하지 않는다.
- 이후 사용자가 Discord 명령의 파일 접수와 호스트 승인 발행을 추가로 요청했다. 이 범위의 현재 계약·운영 반영 상태는 [DISCORD-WORKS.md](DISCORD-WORKS.md)를 따른다. 웹 참여자 작성본 API가 임의 파일 경로를 받지 않는 규칙은 유지한다.
- `studio_drafts`는 계정/업체별 비공개 작성본과 증가하는 revision을 저장한다. 공개 승인본의 자기 업체 데이터 해시를 비교하며, 오래된 승인본·다른 창 저장을 409로 거부한다. 오래된 작성본은 JSON으로 내려받아 수동 비교한다.
- `studio_proposals`는 제출 당시 사본을 고정한다. 이유 1–1,000자, 요청 본문 256KiB, 계정별 미결 요청 5개, 동일 내용 중복 제출 거부, Cloudflare 요청 제한 30회/60초를 사용한다. 제출은 공개 콘텐츠를 바꾸지 않는다.
- 호스트는 요청 JSON을 내려받아 로컬 편집기의 ‘변경안 가져오기’로 연다. 기준 해시·소속·형식·참조·충돌·파일 검증 뒤 미리 보고 기존 저장/백업/콘텐츠 배포를 사용한다. 발행 결과 확인 API는 실제 공개 콘텐츠가 요청 내용과 일치할 때만 published로 바꾼다. 반려도 호스트만 가능하다. API에 Cloudflare 배포 키를 주지 않는다.
- `/api/studio/login`, `callback`, `session`, `logout`, `draft`, `submit`, `proposals`, `proposal`, `reject`, `published`는 동적 서버 경로다. DB/비밀/요청 제한 미설정은 503으로 닫힌다. 쓰기는 정규 출처 `https://induo.works`·JSON 요청만 받으며 로컬 인증 우회 기능은 없다.

## 외부 작품 링크 (로컬 구현, 운영 배포 전)

호스트 로컬 편집기 ‘작품’과 참여자 ‘Works’의 외부 작품 링크 필드에 URL을 입력한다. Work 참조로 집 안 원하는 층에 전시하며, 기존 작성본 저장·호스트 검토·콘텐츠 발행 절차를 그대로 사용한다.

- YouTube 영상 URL은 `youtube-nocookie.com` 공식 임베드, SoundCloud 개별 공개 곡은 공식 위젯으로 표시한다. 단축 SoundCloud 링크와 재생목록은 지원하지 않는다.
- GitHub `github.com/소유자/저장소/blob/참조/파일` 또는 `raw.githubusercontent.com` 파일 URL은 정규화해 사용한다. 이미지 PNG/JPEG/WebP/GIF/AVIF, 음원 OGG/MP3/M4A를 지원한다. HTML·SVG·임의 사이트 임베드는 받지 않는다. GitHub 공개 여부와 실제 MIME은 파일 서비스 응답에 달려 있다.
- 마을·실내 초기 로딩에는 외부 플레이어를 만들지 않는다. 전시물 클릭 시에만 iframe/이미지/audio를 생성하며 팝업 닫기·다른 물체 선택·층/지역 이동 시 제거한다. 직접 음원은 `preload=none`, 외부 플레이어는 자동재생하지 않는다. Works 상세 페이지도 ‘열기’ 클릭 후 생성한다.
- GitHub 이미지 링크는 대표 이미지가 없는 Work의 Works 카드에 지연 로딩 미리보기로 사용한다. 외부 링크는 업로드 파일 목록에 포함하거나 서버에서 다운로드하지 않는다.
- 허용된 iframe·이미지·음원 출처만 CSP에 추가한다. 외부 콘텐츠가 삭제되거나 임베드가 막혔을 때 사용할 원본 링크를 항상 표시한다. 클릭 후 해당 서비스로 브라우저 요청이 전송된다.

브라우저에서 테스트 변경안 JSON 다운로드 → 로컬 가져오기 → 2층 미리보기 → 저장 없이 변경 버리기까지 확인했다. 외부 링크 기능의 테스트 자료는 로컬 미리보기 전용이며 실제 작품 데이터에 저장하지 않는다.

외부 링크 검증: 전체 테스트 75개, Astro 검사·빌드·52개 내부 경로 검사 통과. Chrome에서 전시물 클릭 후 YouTube 공식 플레이어와 GitHub 실제 이미지 표시, 닫기 후 iframe 제거를 확인했다. SoundCloud는 생성된 위젯과 공식 문서의 예시 위젯 모두 이 브라우저에서 빈 화면이어서 실제 재생 확인은 남아 있다. 실제 모바일·운영 CSP 아래의 재생은 배포 후 검증 대상이다.

## 운영 연결에 필요한 설정

아래는 운영 연결 상태와 이후 관리 절차다. 재사용한 기존 앱 ID는 `1469603219695992895`다.

1. 사용자 승인으로 기존 Wrangler 권한을 유지하고 D1 쓰기만 추가한 재로그인을 완료했다. 다른 제품의 전체 권한을 일괄 추가하지 않았다.
2. 전용 D1 `induoworks-studio`(APAC)를 생성하고 `wrangler.jsonc`에 `STUDIO_DB` 바인딩과 실제 DB ID를 기록했다. `migrations/0001_studio.sql`, `0002_studio_hosts.sql`은 로컬·원격 모두 적용했다. 사이트 코드에도 배포해 연결했다.
3. Discord Developer Portal → 기존 앱 → OAuth2 → Redirects에 `https://induo.works/api/studio/callback`을 등록·저장했다. `identify`만 사용하며 봇 권한을 추가하지 않았다.
4. `DISCORD_CLIENT_ID`는 Wrangler vars에 등록했다. Cloudflare Workers & Pages → induoworks-site → Settings → Variables and Secrets에 `DISCORD_CLIENT_SECRET`(Secret)을 등록한다. 사용자가 직접 새로 발급해 등록을 완료했고, 비밀 값은 읽지 않고 이름 존재만 확인했다. 비밀을 채팅·이슈·Git에 넣지 않는다. Client Secret 생성/재설정·입력은 사용자가 직접 수행한다.
5. 사용자가 제공한 본인 Discord ID를 원격 DB의 `studio_hosts`와 `studio_members`의 Frondward에 연결했다. 이후 참여자는 관리자가 확인한 Discord 계정 ID와 기존 업체 ID를 `studio_members(user_id,worker_id)`에 연결한다. ID는 사용자명/닉네임이 아니라 Discord의 숫자 ID다. 브라우저 작성본으로 권한을 등록할 수 없다.
6. 사용자 승인 후 사이트 코드·콘텐츠 배포와 main 반영을 완료했다. 공개 52개 경로, 미로그인 작성본·검토 API 401, 로컬 전용 편집 경로 404를 확인했다. 실제 계정 로그인·비공개 작성/복원·음악 전시·검토 요청/반려를 확인했다. 최초 로그인 대기 후 임시 확인 오류는 새 로그인 요청으로 복구했고, 이후 실패 시 JSON 오류 대신 재시도 화면으로 돌아가도록 보완했다. 별도 참여자 계정과 모바일 실기기 검증은 남아 있다.

D1 설정 예시(실제 ID를 사용해야 하며 예시 ID를 운영 설정에 넣지 않는다):

```json
{"d1_databases":[{"binding":"STUDIO_DB","database_name":"induoworks-studio","database_id":"실제 데이터베이스 ID","migrations_dir":"migrations"}]}
```

## 검증과 남은 범위

Node SQLite 기반 테스트로 실제 SQL, state 위조·재사용, 세션 만료, 계정 소속/권한 회수, CSRF, 요청 제한, 타사 작품 ID·소속 변경, 새 파일 거부, 작성본 동시 저장, 중복 제출, 오래된 승인본, 공개 콘텐츠 불일치 시 발행 성공 거부를 확인한다. 브라우저 실제 검증에서 찾은 입력 반영 문제를 input 이벤트와 미완성 입력 보존으로 고치고, 새 탭에서 입력한 제목이 유지됨을 확인했다. 변경안 API는 JSON 첨부 응답을 제공하지만 브라우저 다운로드 도구가 완료 신호를 받지 못했고 Chrome 내부 다운로드 화면은 도구 보안 정책으로 확인할 수 없어 사용자 파일 확인을 요청했다. 이후 사용자가 알려준 Downloads 폴더의 변경안 JSON으로 실제 가져오기·2층 미리보기·저장 없이 변경 버리기까지 확인했다.

계단·캐릭터 이동, 참여자 직접 업로드/R2, 공동 제작 작품의 편집 정책, 권한 관리 GUI, 원격 자동 발행은 포함하지 않는다. 현재 기본 자동 전시의 작품 9개·이미지 4개 한도는 유지한다. 프로젝트 정적 상세/SEO 갱신은 사이트 재빌드 대상이지만 범용 상세와 Works·씬의 데이터 변경은 콘텐츠 발행만 필요하다.

인증 근거: [Discord 공식 OAuth2 문서](https://docs.discord.com/developers/topics/oauth2).

## 2026-10-18 씬 내부 편집 화면

씬 오른쪽 아래의 설정 아이콘은 같은 페이지에서 작업실 관리 도구를 연다. 전체 화면은 옆의 별도 아이콘으로 전환하며, 설정을 닫아도 전체 화면 상태와 작성본을 유지한다. 전체 화면 종료·Esc는 스크롤과 외부 요소의 접근성을 복원한다. 꾸미기 도구와 실행 취소는 하단에 두고, 작품 선택·공간/선택 물체 설정·저장/변경 요청은 접힌 패널에서 연다. 작품 선택 후 목록을 접어 배치 공간을 확보한다. Works·이미지·음악 관리와 비공개 저장·변경 요청 API는 유지한다.

수동 전시물은 첫 터치로 선택하고 선택된 전시물을 다시 드래그하면 이동한다. 6px 미만 손 떨림은 이동으로 처리하지 않는다. 빈 바닥 드래그는 기존 시점 이동을 사용한다. 드래그 기록 묶음·충돌 검사를 유지하며 배치 뒤 남은 클릭 억제 상태가 도구 버튼을 막지 않게 한다. 자동 배치된 기본 전시물의 자유 이동과 원격 호스트 발행은 이번 범위가 아니다. 호스트 로컬 편집기 화면은 유지한다.

검증은 실제 계정·DB·배포와 분리한 localhost 화면 및 UI 회귀 테스트를 사용한다. 테스트 85개, Astro 진단 오류·경고·힌트 0, 전체 빌드·CSP·53개 내부 경로 검사가 통과했다. 실제 모바일의 핀치·가상 키보드 검증은 남아 있다. 사용자 승인으로 이번 변경의 커밋·main push·자동 검사·공개 배포를 진행하며 최종 반영 기록은 이슈 #2를 따른다.

## 2026-10-18 장소·보기 도구 재배치 — 로컬 작업본

제목 옆 관리 버튼과 상시 계정 헤더를 제거했다. 왼쪽 아래는 마을에서 자기 집으로 가는 집 아이콘, 실내에서 마을로 돌아가는 화살표와 현재 장소 이름이다. 오른쪽 아래는 64px 배율 슬라이더·독립 전체 화면·설정 아이콘이며 같은 높이로 정렬한다. 배율 숫자는 슬라이더 조작 후 900ms 동안만 표시하고, 보이는 동안 누르면 화면에 맞는 배율로 초기화한다. 단색 선 아이콘과 문자형 재생/링크 표시를 사용한다. 계정 선택·로그아웃은 설정 안의 접힌 ‘계정’에 둔다. 미로그인 내 집 이동은 로그인 안내를 연다. 호스트 로컬 편집기의 집 이동·설정 아이콘은 숨겨 참여자 편집과 섞이지 않게 한다.

## 2026-10-18 편집 도구 단순화·LAN 확인 — 로컬 작업본
