# 콘텐츠 편집과 페이지 연결

현재 주민·작품·공지·미디어·음악의 편집 원본은 `content/catalog.json`이다. 공개 사이트는 콘텐츠 전용 Static Assets 배포에서 작은 JSON을 읽는다. 사이트 전체 빌드와 콘텐츠 발행은 별도다. R2는 사용하지 않는다.

## 콘텐츠 발행과 복구

- 제공 주소: `https://induoworks-content.rlaalstn0910.workers.dev/catalog.json`
- `npm run content:deploy`: 목록·참조·파일 형식을 검사하고 콘텐츠만 배포한다. Astro 페이지 전체를 빌드하지 않는다. 발행은 인증된 로컬 Wrangler로만 수행하며 브라우저에 쓰기 키를 넣지 않는다.
- `npm run content:import -- "파일 경로"`: 웹용 파일을 검사하고 해시 이름으로 `content/files/uploads/`에 복사한다. 출력된 `/uploads/…` 경로를 목록에 등록한다. 원본은 수정하지 않는다.
- 음원은 Opus Ogg와 MP3를 등록한다. WAV, 형식과 확장자가 다른 파일, 25MiB 초과 파일은 거부한다. 썸네일은 100KiB 안팎의 작은 웹용 이미지를 권장한다. 이미지는 PNG·WebP·JPEG·AVIF·GIF를 허용하며 SVG/HTML 업로드는 허용하지 않는다. 전체 배포 파일은 2만 개 이하여야 한다. 목록은 1MiB 이하, 각 종류의 항목은 1,000개 이하로 제한한다. 이 검사는 제공된 발행 도구의 제한이며 Cloudflare 대시보드로 직접 올리는 파일까지 통제하지는 않는다.
- 기존 미디어는 `public/`에서 가져오고 새 파일은 `content/files/`에서 가져온다. `content:prepare`는 `.content-dist/`를 만든다. 빌드 시 같은 미디어를 사이트 배포에도 복사하여 내장 방식이 동작한다. 기존 해시 파일을 바꾸지 말고 새 파일을 추가한다.
- JSON의 브라우저 캐시는 60초, 해시 미디어는 1년이다. 공개 JSON에는 개인정보나 비밀을 넣지 않는다. 새 탭·새로고침에서 새 목록을 확인하며 이미 열린 장면을 실시간으로 변경하지 않는다.
- 조회는 2.5초 이내의 정상 JSON만 채택한다. HTTP 오류·오프라인·잘못된 스키마는 사이트에 내장된 마지막 빌드 시점 데이터로 돌아간다. JavaScript가 꺼져도 정적 Works·Workers·기존 상세 링크를 볼 수 있다.
- `?content=embedded`를 붙이면 해당 페이지에서 외부 조회를 건너뛴다. `PUBLIC_CONTENT_MODE=embedded`로 사이트를 빌드하면 전체를 기존 내장 방식으로 운영할 수 있다. 내장 데이터는 별도 편집 원본이 아니라 같은 JSON의 빌드 시점 사본이다.
- 콘텐츠 배포를 이전 Cloudflare 버전으로 되돌릴 수 있다. 재현에 필요한 JSON과 새 파일은 Git으로 보존한다. 콘텐츠 배포와 Git push는 별개이며, 기존 Git 연동의 자동 사이트 빌드는 별도로 작동할 수 있다.

`Induohood`, Works, Workers, 프로젝트 상세는 동일한 목록을 사용한다. 기존 `/work/<slug>/` 정적 주소를 유지하고, 새 프로젝트는 `/work/detail/?id=<slug>` (한국어는 `/ko/work/detail/`)에서 열어 라우트 재빌드 없이 추가할 수 있다. 이 범용 상세 주소는 noindex다. 검색 노출용 정적 상세·사이트맵·메타 설명은 사이트 재빌드 시 갱신된다. 목록에 없는 상세는 찾을 수 없다는 안내를 표시한다.

새로운 건물 모양·오브젝트 동작·필드 종류·UI·언어와 지형 종류는 코드 배포 대상이다. 기존 잔디·길·물 타일과 나무·풀·간판 배치는 콘텐츠 편집 대상이다. 현재 편집기는 한 작업실에 프로젝트 9개·이미지 4개까지 허용한다. 새 집으로 가는 도로는 자동으로 생기지 않는다. R2·대용량 영상 운영은 계속 보류 범위다. 요구사항은 [이슈 #2](https://github.com/minsueverywhere/induoworks-site/issues/2)에서 관리한다.

## 로컬 편집기

1. 저장소에서 `npm run content:edit`를 실행하고 `http://127.0.0.1:4323/__editor/`를 연다. Astro 백그라운드 서버로 실행된다. 포트가 사용 중이면 실행 로그에 나온 실제 주소의 `/__editor/`를 연다. 종료·상태·로그는 `npm run astro -- dev stop`, `dev status`, `dev logs`로 관리한다. 이미 일반 미리보기가 실행 중이면 그 서버 상태를 확인한 뒤 편집 서버를 실행한다.
2. **장면 편집**과 **물체 이동** 도구로 집·나무·풀·마을 간판·공고판·마스코트를 드래그한다. 빈 바닥 드래그는 시점 이동이다. 오른쪽 장면 탭의 X/Y로도 수정한다. 집은 정수, 다른 물체의 드래그는 ¼칸 단위로 맞춘다. 나무·풀은 크기(.5–1.6)를 조절하거나 삭제할 수 있다. 격자는 편집 중에만 표시한다. 장면 편집을 끄면 집에 들어가 전시와 음악을 확인할 수 있다.
   도구에서 **잔디·길·물**을 골라 클릭·드래그로 타일을 칠하고, **나무·풀 추가**로 한 개씩 배치한다. **장식 지우기**는 나무·풀만 지운다. 24×24 범위와 지형·물체 겹침을 검사한다. 물체가 있는 곳을 길·물로 바꾸려면 물체를 먼저 옮긴다. 마스코트는 길에도 놓을 수 있다.
**실행 취소 / 다시 실행** 버튼 또는 Ctrl+Z / Ctrl+Shift+Z(맥은 ⌘)를 쓴다. 타일 칠하기·장식 지우기·물체 이동은 한 번의 드래그를 한 단계로 묶고, 글자 입력은 해당 필드 편집을 마칠 때 묶는다. 입력 필드 안의 단축키는 브라우저의 글자 편집 기능을 유지한다. 최근 50단계를 메모리에 보관하며 저장 후에도 되돌릴 수 있다. 다시 불러오기·새로고침은 기록을 초기화한다. 되돌려도 이미 업로드한 파일은 지우지 않는다. 편집기와 씬은 사이트와 같은 테마 설정을 따르며, 사이트 미리보기 링크에서는 전체 페이지를 확인할 수 있다.

집·마을 간판·공고판·나무의 **점유 너비·깊이(칸)**를 설정한다. 집은 업체 탭의 `workers[].house.width/depth`, 다른 물체는 장면 탭의 `world.sign`, `world.noticeboard`, `world.decorations` 나무 항목의 `width/depth`가 원본이다. 생략하면 집은 2×2칸, 다른 물체는 1×1칸이다. X/Y는 앞쪽 기준 칸이고, 다른 물체의 분수 좌표는 가까운 칸을 기준으로 X-width+1…X / Y-depth+1…Y에 영역을 예약한다. 크기는 1–24 정수이고 전체 영역이 마을 안의 잔디여야 한다. 마스코트만 길 위에도 놓을 수 있다.

선택한 물체와 이동·신규 배치 후보의 점유 칸을 표시한다. 다른 물체·길·물·마을 경계와 충돌하는 칸만 빨갛게, 나머지는 Dewy Sand로 표시하며 같은 계산으로 실제 배치·크기 변경·저장도 검사한다. 마지막 유효 위치에서 벗어나 충돌하는 이동은 적용하지 않는다. 타일 도구 역시 전체 점유 영역을 보호한다. 예전의 중심점 거리 제한은 실제 점유 칸 검사로 대체했다. 바닥 풀은 나무·간판 아래에 둘 수 있지만 집 영역에는 놓을 수 없다. 점유 크기는 배치 공간을 예약하며 그림의 크기·외형과는 별개다. 실행 취소와 콘텐츠 저장·발행에도 함께 포함된다.

3. 오른쪽 탭에서 업체·작품·이미지·음악을 추가하거나 수정한다. ID는 자동 생성되어 고정된다. 한국어·영어 문구와 소속을 입력한다. 이미지 업로드는 원본과 640px 미리보기·96px 배지를 해시 이름으로 보관한다. 음악은 관련 프로젝트와 작곡가·팀·회사 이름을 입력하고 미리 인코딩한 Opus Ogg와 MP3를 각각 올린다. 편집기는 WAV 변환 도구가 아니다.
4. **미리보기 갱신**은 저장하지 않은 데이터를 실제 마을에 적용한다. **저장**은 파일과 참조를 검사한 뒤 `content/catalog.json`을 교체한다. 이전 파일은 `.wrangler/editor-backups/`에 자동 백업한다. 다른 창·도구가 저장한 경우 덮어쓰지 않고 재로드를 요구한다. 다시 불러오기는 저장하지 않은 수정만 버린다. 업로드 파일은 로컬에 남지만 참조하지 않으면 발행 목록에 새로 포함되지 않는다.
5. 저장 후 **콘텐츠만 배포**를 누르면 기존 인증을 쓰는 로컬 Wrangler가 콘텐츠 전용 저장소만 발행한다. 웹페이지 전체 빌드나 Git commit/push는 하지 않는다. 실패하면 저장본은 유지되고 배포 결과에 오류가 나온다. 정상 발행 후 새로고침한 공개 페이지에 약 1분 안에 반영된다. Wrangler 로그인이 만료되면 터미널에서 공식 로그인 절차를 완료한 뒤 재시도한다.

이 화면과 저장 API는 `INDUO_EDITOR=1`인 개발 서버에서만 열린다. 명령은 127.0.0.1에 바인딩하고 API는 loopback 접속·Host·동일 출처·실행별 토큰을 검사한다. 브라우저에는 Cloudflare 인증 정보를 전달하지 않는다. 공개 빌드에 편집 코드가 들어가지 않는지도 검사한다. 서버를 인터넷에 노출하는 원격 관리자 기능은 제공하지 않는다.

장면 원본은 같은 JSON의 `world`다. 잔디·길·물 576개 타일, 이름표와 공고판·마스코트 좌표, 나무·풀 장식을 저장한다. 집 좌표는 기존 `workers[].house`를 그대로 참조한다. 구형 콘텐츠에 world가 없으면 `village-world.mjs`가 기존 지형의 고정 기본값을 만들며, 내장 방식과 공개 조회 모두 같은 해석을 사용한다. 저사양 환경의 그리기 비용과 편집 실수를 제한하기 위해 나무·풀은 합계 300개까지 허용한다. 지형은 다시 그릴 때 캐시하며 격자·배치 도구는 공개 코드에 포함되지 않는다. 추가 배치 때문에 새 이미지 파일을 다운로드하지 않는다.

음악의 기존 `music`은 호환용 기본곡이다. 추가 음악은 `tracks`, 전체 기본곡 선택은 `musicId`, 업체별 선택은 `workers[].musicId`로 참조한다. Works·Workers와 주크박스는 같은 음악 항목을 읽으며 기존 기본곡도 Works에 포함한다. 선택적 `artist`는 작곡가·팀·회사 표시이며 없으면 예전 `project` 값을 쓴다. 주크박스 팝업은 곡명 - 제작자, 재생/일시정지, 재생 위치·현재/전체 시간과 해당 곡으로 필터한 Works 링크만 표시한다. 음량 UI는 제거했다. 어떤 곡도 마을 진입 때 다운로드하지 않는다. 한 번에 한 곡을 재생하며 다른 작업실의 주크박스를 켜면 이전 곡을 멈춘다. 이 스키마를 처음 적용할 때는 사이트 코드도 한 번 배포해야 하며 이후 곡 추가·교체는 콘텐츠 발행만으로 반영된다.

## 사이트 테마

공통 테마는 `src/styles/global.css`에서 관리한다. 라이트는 승인된 Cream 배경과 Induo Blue 글자, 다크는 Induo Blue의 sRGB 채널을 25%로 줄인 배경(반올림)과 Cream 글자를 사용한다. 다크의 링크·초점 표시는 읽기 쉬운 Lens Blue를 사용한다. 보조 글자와 테두리는 각 테마의 글자·배경에서 파생한다. 폰트는 `system-ui`와 `ui-monospace`를 우선하는 기기 기본 글꼴이며 웹폰트를 다운로드하지 않는다.
GPU Interference 실험은 사이트에서 제거했으며 `labs`는 현재 비어 있다.
브라우저의 자동 다크 변환이 사이트의 테마 색을 다시 바꾸지 않도록 `color-scheme: only light` / `only dark`를 선언한다. 배경은 sRGB의 고정 색이다. OS의 블루라이트 필터·색상 보정이나 디스플레이 자체의 색 차이는 사이트가 제어하지 못한다.

| 편집할 사실 | 원본 | 반영 위치 |
|---|---|---|
| 개발사·개인의 ID, 이름, 소개, 집 위치 | `content/catalog.json`의 `workers` | Workers, Induohood 집, 작품의 제작자 링크 |
| 프로젝트 제목·소개·분야·상태·태그·소속 | 같은 JSON의 `projects` | Works, 작품 상세, Workers의 작품 목록, 마을 작업실 |
| 실험의 제목·소개·태그 | 같은 파일의 `labs` | Works, 실험 상세 |
| 아트워크 제목·소속·태그·파일 경로 | `content/catalog.json`의 `media` | Works, Workers의 작품 목록, 작업실 전시 |
| 지형 타일·장식·마을 간판·공고판·마스코트 위치 | 같은 JSON의 `world` | Induohood와 로컬 장면 편집기 |
| 메뉴 및 공통 문구 | `src/i18n.ts` | 한국어·영어 공통 화면 |
| 실제 공지의 ID, 제목, 본문, 선택적 링크 | `content/catalog.json`의 `notices` | 공고판의 메모지와 공지 팝업 |

`workerIds`는 `workers[].id`를 참조한다. 개발사 쪽에 작품 제목이나 별도의 작품 배열을 복사하지 않는다.
`worksByWorker()`와 작품 목록은 같은 원본에서 파생한다. 같은 작품이 여러 제작자에게 속해도 각 방의 물체 ID는 제작자 ID를 포함해 충돌하지 않는다.

## 추가하는 순서

1. JSON의 `workers`에 고유 ID와 영어·한국어 소개를 추가한다. 마을에 집을 표시하려면 `house: { x, y }`를 지정한다. 기존 집·길·공고판과 겹치지 않는 24×24 범위의 위치를 골라 화면으로 확인한다.
2. JSON의 `projects`에 작품을 추가하고 `workerIds`에 해당 제작자 ID를 넣는다. `kind`, `status`, `stack`, 선택적인 `tags`가 Works 필터에 자동 반영된다. Works 대표 이미지는 선택적인 `thumbnail`에 웹용 경로·크기·영한 대체 텍스트·이미지 종류를 등록한다. 이미지가 없으면 준비 중 표시를 사용한다.
3. 아트워크는 `scripts/prepare-village-media.mjs`로 작은 배지·미리보기·원본을 준비하고 JSON의 `media`에 메타데이터를 한 번 등록한다. 제작자 로고는 `logoMediaId`로 그 항목의 ID를 참조한다. 원본은 명시적으로 열 때만 요청한다.
4. 콘텐츠만 바꾸면 `npm run content:deploy` 후 한국어·영어·모바일을 확인한다. 코드도 바꾸면 `npm run build`로 전체 테스트·타입·파일 참조를 검사하고 사이트를 배포한다.

방은 현재 고정 배치이며 프로젝트 전시대 9개를 기준으로 한다. 작품 수가 그 범위를 넘으면 방 배치/페이지 이동을 먼저 확장한다. 아트워크 전시대도 추가 시 겹침을 확인한다.
주크박스는 기본 Sunlit Circuit 또는 위에서 선택한 곡을 반복 재생한다. `src/scripts/village-music.mjs`가 처음 재생 요청에서만 오디오 요소와 파일 주소를 연결한다. 기본은 Ogg/Opus, 지원하지 않는 브라우저는 MP3를 사용한다. 자동으로 다음 곡을 넘기는 재생 목록은 없다. 원본이 반복용으로 준비되어 있으므로 페이드나 크로스페이드를 추가하지 않는다. 변환 원본·옵션과 실제 기기 미확인 사항은 [HANDOFF.md](HANDOFF.md)를 본다.

## Works 보기

기본 보기는 게시글(Posts) 가로 목록이다. 이미지 주변 여백은 투명하며 태그는 본문 아래, 상태는 우측 하단에 표시한다. 모자이크는 이미지의 원래 비율을 살리는 다단 배치다. 갤러리는 4:3 카드 안에 원본 전체를 표시하고 남는 공간을 같은 이미지의 흐린 배경으로 채운다.
별도 이미지 파일을 추가하지 않고 기존 웹용 이미지를 CSS 배경으로 재사용한다. 명시적인 `view=gallery`/`view=mosaic`/`view=posts` URL은 해당 보기를 유지한다.
갤러리·모자이크의 정보는 마우스오버 또는 키보드 초점 시 카드 위에 표시한다. 모바일에서는 ⓘ 버튼으로 열고 닫는다. 게시글 보기에서는 정보를 상시 표시한다.
검색·필터는 처음부터 펼쳐진 접이식 패널이며, 적용된 조건 수는 패널 제목에 표시한다.
검색은 제목·소개·연도·태그·제작자 이름을 대상으로 하며 공백으로 나눈 단어를 모두 포함해야 한다.
제작자·분야·상태·태그는 함께 적용된다. 검색/필터/보기는 URL에 반영되어 같은 목록으로 연결할 수 있다.
JavaScript가 꺼져도 전체 작품 링크는 정적 HTML로 제공한다. 글 작성·업로드용 관리자 화면은 포함하지 않는다.

## 문의 양식

`ContactView.astro`는 테마 배경 위에 이름·이메일·본문을 배치한다. Turnstile 확인이 완료된 동안에만 제출할 수 있으며, 만료·연결 실패는 별도로 안내한다. 확인 위젯은 방문자의 조작이 필요할 때 표시한다. 제출 후 토큰을 갱신하고, 오류가 나면 작성한 내용을 보존한다. API는 입력 오류·확인 실패·서비스 장애를 구분하는 오류 코드를 반환하며, 발송 서비스가 요청을 수락해야 성공으로 처리한다. 성공은 최종 수신함 도착을 보장하지 않는다.
공개 문의 주소는 `src/config.ts`의 `site.email`에서 관리한다. 값이 있으면 메일 앱에서 직접 작성하는 `mailto:` 링크를 폼 위에 표시한다. 이 링크는 JavaScript 없이도 동작하고 문의 API를 거치지 않는다.
오프라인 발송·검증 오류 회귀 검사는 `npm test`로 실행한다. 실제 메일은 보내지 않는다. 요청 제한과 빌드·배포 절차의 원본은 README의 Security notes 및 Deploying을 따른다.

## 대표 이미지 출처

대표 이미지의 웹용 사본은 `public/work/media/`에서 제공한다. 원본은 변경하지 않고 전체 구도를 유지한 채 640px WebP(quality 72)로 변환했다. 파일명 뒤 12자리는 원본 SHA-256 앞부분이다. 콘셉트 아트는 실제 게임 화면으로 표시하지 않는다.

| 프로젝트 | 원본 출처 | 이미지 종류 |
|---|---|---|
| grench-boss | workspace `archive/images/grench-boss-concept-art/grounded_airship_demo/first_level_jungle_coast_concept.png` | 콘셉트 아트 |
| yggbound | 사용자가 제공한 `Pasted Image 20260817234540_048.png` | 로고 아트워크 |

Rooftop Alien은 사용자 요청으로 대표 이미지 적용을 보류했다.
Induohood 이름은 `src/i18n.ts`의 홈 메뉴 문구를 제목·입체 간판·지도 대체 텍스트·캡션에서 공유한다. 최초 및 숫자 클릭 초기화 배율은 `defaultZoom()`에서 공유한다. 마을 창이 520px 미만이면 80%, 이상이면 110%이며 작업실은 폭·높이에 맞춰 최대 100%로 계산한다. 창 크기를 바꾸는 동안에는 조절한 배율을 보존하고 숫자를 누를 때 현재 크기로 다시 계산한다.
Induohood 제목 옆 물음표는 호버·초점에서 짧은 소개, 클릭에서 선택형 체험 튜토리얼을 연다. 단계의 원본은 `src/scripts/village-tutorial.mjs`이며 패닝·확대축소 뒤 Induo Works 집에 들어가 실제 음악 재생과 복귀까지 체험한다. 모바일의 주 포인터가 터치이면 핀치, PC이면 휠로 안내하며 키보드 방향키와 +/−도 진행할 수 있다. 어느 단계든 건너뛰기·Esc로 종료하고 다시 시작할 수 있다. 페이지 나머지는 테마에 맞는 음영으로 덮고 현재 씬·집·주크박스·복귀 버튼에 집중 영역을 표시한다. 안내 표시는 바닥 축에 맞춘 CSS 선·화살표·원으로 그리며 이모지나 별도 이미지 파일을 사용하지 않는다.
집 위치는 `workers` 한 곳에서 관리한다. Induo Works 집의 사이트 전시물은 `projects.workerIds`, 벽면의 개별 소셜 링크는 공통 `socialLinks`에서 파생한다. 소셜 아이콘은 해당 작업실에 들어갈 때 파일 주소를 연결하며, 아이콘을 누르면 외부 채널을 직접 연다. 작업실은 소속 프로젝트·아트워크와 주크박스를 표시한다. 제작자 이름을 표시하는 나무 간판은 왼쪽 벽면의 기울기에 맞춰 집 스프라이트 안에 그린다. 간판의 별도 클릭 영역·소개 팝업은 없으며 집과 함께 선택되고 클릭하면 작업실에 들어간다.
설명 팝업은 선택한 물체 옆의 여유 공간에 배치하고 씬 경계 안으로 제한한다. 같은 물체를 다시 누르면 닫힌다. 팝업 내용이 길면 내부만 스크롤되며, 창 크기가 바뀌면 기준 물체 위치에 맞춰 다시 배치한다.
지도 오른쪽 아래에는 25–160% 배율 슬라이더와 현재 배율을 둔다. 평소에는 반투명하며 호버·초점·조작 중에는 선명해진다. 포인터로 슬라이더를 움직이면 97–103%에서 100%로 스냅된다. 키보드의 1% 단위 조절은 스냅하지 않아 100%에서 벗어날 수 있다. 배율 숫자는 현재 화면 크기에 맞는 기본 배율로 복귀한다. 휠·두 손가락 확대·축소는 기존의 연속 조절을 유지한다.

## 간판·공고판과 지형

왼쪽 위 경계선의 INDUOHOOD 입체 간판을 누르면 마을 소개가 열린다. 공고판은 입구 길 왼편 잔디 공간에 두며, `villageNotices`가 비어 있으면 종이·클릭 영역·아웃라인을 표시하지 않는다. 실제 공지가 있으면 최대 네 장의 종이를 그리고 클릭 시 등록된 전체 공지와 링크를 보여준다. 임시 공지는 등록하지 않는다.
현재 간판·공고판·마스코트 좌표와 길·물·나무·풀은 `content/catalog.json`의 `world`에서 공유한다. `src/scripts/village-layout.mjs`의 지형 함수와 고정 난수는 구형 데이터의 기본 배치를 만드는 데 쓴다. 길의 외곽에만 경계를 그려 타일 사이 선이 생기지 않게 한다. 나무의 간격·크기와 풀의 위치·밀도는 불규칙하지만 방문·다시 그리기마다 변하지 않는다. 간판과 지형은 Canvas 도형으로 그려 추가 이미지 파일을 요청하지 않는다.
간판은 기기 글꼴의 실제 글자 경계를 측정해 일정한 간격으로 배치한다. 측면 두께는 지면의 다른 축을 따라 뒤로 뻗고 바닥 그림자는 그리지 않는다. 공고판 면은 입구 길과 같은 −0.5 기울기를 사용하며 기둥은 길 가장자리 바로 바깥에 둔다. 공지가 하나면 중앙의 큰 메모지에 제목을 표시한다. 현재 주민 모집 공고는 언어에 맞는 Contact 페이지로 연결되며, 링크 문구는 공지의 선택적 `linkLabel`에서 정한다.
