# 콘텐츠 편집과 페이지 연결

현재는 빌드 시점의 공유 데이터를 사용한다. 데이터 수정 후 빌드·배포해야 공개 페이지에 반영된다.
외부 데이터/R2 전환은 [보류 이슈 #2](https://github.com/minsueverywhere/induoworks-site/issues/2)에서만 관리한다.

## 사이트 테마

공통 테마는 `src/styles/global.css`에서 관리한다. 라이트는 승인된 Cream 배경과 Induo Blue 글자, 다크는 Induo Blue의 sRGB 채널을 25%로 줄인 배경(반올림)과 Cream 글자를 사용한다. 다크의 링크·초점 표시는 읽기 쉬운 Lens Blue를 사용한다. 보조 글자와 테두리는 각 테마의 글자·배경에서 파생한다. 폰트는 `system-ui`와 `ui-monospace`를 우선하는 기기 기본 글꼴이며 웹폰트를 다운로드하지 않는다.
GPU Interference 실험은 사이트에서 제거했으며 `labs`는 현재 비어 있다.
브라우저의 자동 다크 변환이 사이트의 테마 색을 다시 바꾸지 않도록 `color-scheme: only light` / `only dark`를 선언한다. 배경은 sRGB의 고정 색이다. OS의 블루라이트 필터·색상 보정이나 디스플레이 자체의 색 차이는 사이트가 제어하지 못한다.

| 편집할 사실 | 원본 | 반영 위치 |
|---|---|---|
| 개발사·개인의 ID, 이름, 소개, 집 위치 | `src/config.ts`의 `workers` | Workers, Induohood 집, 작품의 제작자 링크 |
| 프로젝트 제목·소개·분야·상태·태그·소속 | 같은 파일의 `projects` | Works, 작품 상세, Workers의 작품 목록, 마을 작업실 |
| 실험의 제목·소개·태그 | 같은 파일의 `labs` | Works, 실험 상세 |
| 아트워크 제목·소속·태그·파일 경로 | `src/village-media.ts` | Works, Workers의 작품 목록, 작업실 전시 |
| 메뉴 및 공통 문구 | `src/i18n.ts` | 한국어·영어 공통 화면 |
| 실제 공지의 ID, 제목, 본문, 선택적 링크 | `src/config.ts`의 `villageNotices` | 공고판의 메모지와 공지 팝업 |

`workerIds`는 `workers[].id`를 참조한다. 개발사 쪽에 작품 제목이나 별도의 작품 배열을 복사하지 않는다.
`worksByWorker()`와 `workCatalog()`는 원본에서 매번 파생한다. 같은 작품이 여러 제작자에게 속해도 각 방의 물체 ID는 제작자 ID를 포함해 충돌하지 않는다.

## 추가하는 순서

1. `workers`에 고유 ID와 영어·한국어 소개를 추가한다. 마을에 집을 표시하려면 `house: { x, y }`를 지정한다. 기존 집·길·공고판과 겹치지 않는 24×24 범위의 위치를 골라 화면으로 확인한다.
2. `projects`에 작품을 추가하고 `workerIds`에 해당 제작자 ID를 넣는다. `kind`, `status`, `stack`, 선택적인 `tags`가 Works 필터에 자동 반영된다. Works 대표 이미지는 선택적인 `thumbnail`에 웹용 경로·크기·영한 대체 텍스트·이미지 종류를 등록한다. 이미지가 없으면 준비 중 표시를 사용한다.
3. 아트워크는 `scripts/prepare-village-media.mjs`로 작은 배지·미리보기·원본을 준비하고 `villageMedia`에 메타데이터를 한 번 등록한다. 제작자 로고는 `logoMediaId`로 그 항목의 ID를 참조한다. 원본은 명시적으로 열 때만 요청한다.
4. `node --test scripts/work-content.test.mjs scripts/village-camera.test.mjs scripts/village-layout.test.mjs`, `npm run check`, `npm run build` 후 한국어·영어와 모바일 폭을 확인한다.

방은 현재 고정 배치이며 프로젝트 전시대 9개를 기준으로 한다. 작품 수가 그 범위를 넘으면 방 배치/페이지 이동을 먼저 확장한다. 아트워크 전시대도 추가 시 겹침을 확인한다.
현재 주크박스는 예시음을 사용한다. 실제 음악 파일의 등록·재생 목록은 아직 구현하지 않았다.

## Works 보기

기본 보기는 게시글(Posts) 가로 목록이다. 이미지 주변 여백은 투명하며 태그는 본문 아래, 상태는 우측 하단에 표시한다. 모자이크는 이미지의 원래 비율을 살리는 다단 배치다. 갤러리는 4:3 카드 안에 원본 전체를 표시하고 남는 공간을 같은 이미지의 흐린 배경으로 채운다.
별도 이미지 파일을 추가하지 않고 기존 웹용 이미지를 CSS 배경으로 재사용한다. 명시적인 `view=gallery`/`view=mosaic`/`view=posts` URL은 해당 보기를 유지한다.
갤러리·모자이크의 정보는 마우스오버 또는 키보드 초점 시 카드 위에 표시한다. 모바일에서는 ⓘ 버튼으로 열고 닫는다. 게시글 보기에서는 정보를 상시 표시한다.
검색·필터는 처음부터 펼쳐진 접이식 패널이며, 적용된 조건 수는 패널 제목에 표시한다.
검색은 제목·소개·연도·태그·제작자 이름을 대상으로 하며 공백으로 나눈 단어를 모두 포함해야 한다.
제작자·분야·상태·태그는 함께 적용된다. 검색/필터/보기는 URL에 반영되어 같은 목록으로 연결할 수 있다.
JavaScript가 꺼져도 전체 작품 링크는 정적 HTML로 제공한다. 글 작성·업로드용 관리자 화면은 포함하지 않는다.

## 문의 양식

`ContactView.astro`는 테마 배경 위에 이름·이메일·본문을 배치한다. Turnstile 확인이 완료된 동안에만 제출할 수 있으며, 만료·연결 실패는 별도로 안내한다. 확인 위젯은 방문자의 조작이 필요할 때 표시한다. 제출 후 토큰을 갱신하고, 오류가 나면 작성한 내용을 보존한다. API는 입력 오류·확인 실패·서비스 장애를 구분하는 오류 코드를 반환하며, 발송 서비스가 요청을 수락해야 성공으로 처리한다. 성공은 최종 수신함 도착을 보장하지 않는다.
공개 문의 주소는 `src/config.ts`의 `site.email`에서 관리한다. 값이 있으면 메일 앱에서 직접 작성하는 `mailto:` 링크를 폼 위에 표시한다. 이 링크는 JavaScript 없이도 동작하고 문의 API를 거치지 않는다.
오프라인 발송·검증 오류 회귀 검사는 `npm test`로 실행한다. 실제 메일은 보내지 않는다. 요청 제한과 빌드·배포 절차의 원본은 README의 Security notes 및 Deploying을 따른다.

## 대표 이미지 출처

대표 이미지의 웹용 사본은 `public/work/media/`에서 제공한다. 원본은 변경하지 않고 전체 구도를 유지한 채 640px WebP(quality 72)로 변환했다. 파일명 뒤 12자리는 원본 SHA-256 앞부분이다. 콘셉트 아트는 실제 게임 화면으로 표시하지 않는다.

| 프로젝트 | 원본 출처 | 이미지 종류 |
|---|---|---|
| grench-boss | workspace `archive/images/grench-boss-concept-art/grounded_airship_demo/first_level_jungle_coast_concept.png` | 콘셉트 아트 |
| yggbound | 사용자가 제공한 `Pasted Image 20260817234540_048.png` | 로고 아트워크 |

Rooftop Alien은 사용자 요청으로 대표 이미지 적용을 보류했다.
Induohood 이름은 `src/i18n.ts`의 홈 메뉴 문구를 제목·입체 간판·지도 대체 텍스트·캡션에서 공유한다. 최초 및 숫자 클릭 초기화 배율은 `defaultZoom()`에서 공유한다. 마을 창이 520px 미만이면 80%, 이상이면 110%이며 작업실은 폭·높이에 맞춰 최대 100%로 계산한다. 창 크기를 바꾸는 동안에는 조절한 배율을 보존하고 숫자를 누를 때 현재 크기로 다시 계산한다.
Induohood 제목 옆 물음표는 호버·초점에서 짧은 소개, 클릭에서 선택형 체험 튜토리얼을 연다. 드래그 → Induo Works 집 입장 → 확대·축소 순으로 실제 조작을 감지하며, 모바일의 주 포인터가 터치이면 핀치, PC이면 휠로 안내한다. 키보드 방향키와 +/−도 진행할 수 있다. 어느 단계든 건너뛰기·Esc로 종료하고 다시 시작할 수 있다. 튜토리얼은 페이지 나머지를 테마에 맞는 음영으로 덮고 현재 씬 또는 집에 집중 영역을 표시한다. 안내 아이콘은 바닥 축에 맞춘 드래그 화살표, 클릭 손, 핀치 손·마우스 이모지를 사용하며 별도 이미지 파일은 없다.
집 위치는 `workers` 한 곳에서 관리한다. Induo Works 집의 사이트 전시물은 `projects.workerIds`, 소셜 전시물의 링크는 공통 `socialLinks`에서 파생한다. 다른 작업실은 소속 프로젝트·아트워크와 예시 주크박스를 표시한다. 집 앞 말뚝 간판은 이름과 Workers 링크를 같은 제작자 정보에서 파생하며 집 벽에는 부착하지 않는다.
설명 팝업은 선택한 물체 옆의 여유 공간에 배치하고 씬 경계 안으로 제한한다. 같은 물체를 다시 누르면 닫힌다. 팝업 내용이 길면 내부만 스크롤되며, 창 크기가 바뀌면 기준 물체 위치에 맞춰 다시 배치한다.
지도 오른쪽 아래에는 25–160% 배율 슬라이더와 현재 배율을 둔다. 평소에는 반투명하며 호버·초점·조작 중에는 선명해진다. 포인터로 슬라이더를 움직이면 97–103%에서 100%로 스냅된다. 키보드의 1% 단위 조절은 스냅하지 않아 100%에서 벗어날 수 있다. 배율 숫자는 현재 화면 크기에 맞는 기본 배율로 복귀한다. 휠·두 손가락 확대·축소는 기존의 연속 조절을 유지한다.

## 간판·공고판과 지형

왼쪽 위 경계선의 INDUOHOOD 입체 간판을 누르면 마을 소개가 열린다. 공고판은 입구 길 왼편 잔디 공간에 두며, `villageNotices`가 비어 있으면 종이·클릭 영역·아웃라인을 표시하지 않는다. 실제 공지가 있으면 최대 네 장의 종이를 그리고 클릭 시 등록된 전체 공지와 링크를 보여준다. 임시 공지는 등록하지 않는다.
간판·공고판 좌표와 길·연못·고정 난수는 `src/scripts/village-layout.mjs`에서 공유한다. 길의 외곽에만 경계를 그려 타일 사이 선이 생기지 않게 한다. 나무의 간격·크기와 풀의 위치·밀도는 불규칙하지만 방문·다시 그리기마다 변하지 않는다. 간판과 지형은 Canvas 도형으로 그려 추가 이미지 파일을 요청하지 않는다.
간판은 기기 글꼴의 실제 글자 경계를 측정해 일정한 간격으로 배치한다. 측면 두께는 지면의 다른 축을 따라 뒤로 뻗고 바닥 그림자는 그리지 않는다. 공고판 면은 입구 길과 같은 −0.5 기울기를 사용하며 기둥은 길 가장자리 바로 바깥에 둔다. 공지가 하나면 중앙의 큰 메모지에 제목을 표시한다. 현재 주민 모집 공고는 언어에 맞는 Contact 페이지로 연결되며, 링크 문구는 공지의 선택적 `linkLabel`에서 정한다.
